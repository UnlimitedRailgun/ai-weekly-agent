## Future one-run budget and stop rules

For a separately authorized live run:

- Research: at most six logical Responses calls, one per fixed category.
- Curate: at most one logical call.
- Report: at most one logical call.
- Total: at most eight logical calls and eight outbound API HTTP attempts.
- Per logical call: at most one HTTP attempt; process-only
  `OPENAI_MAX_RETRIES=0`.
- Research: `max_tool_calls=4` per category, for at most 24 configured built-in
  web-search tool calls. This is not an HTTP-, page-, or token-count promise.
- Curate/Report: no search tool.
- No retry, fallback, repair, second main execution, model switch, A/B run, or
  quality-motivated rerun.
- Empty or failed paths retain their naturally lower count; eight calls are not
  a target.
- A timeout or lost response consumes its HTTP-attempt allowance even when
  server-side execution or billing remains unknown.

The wrapper records content-free stage/category, requested and response model,
request/response ID when returned, status, duration, actual HTTP-attempt count,
web-search output-item count, and input/output/total plus cached/reasoning token
details when present. Missing usage remains null; incomplete totals are not
reported as complete. The current production request does not gain a new
`max_output_tokens` parameter. No current price was verified offline, so a
dollar estimate and hard dollar ceiling are **unavailable**; no price was
invented.

Stop before or during the run on any fingerprint, seed, SDK, model, timeout,
proxy, endpoint, cwd, target-publication, logical-sequence, HTTP-budget, schema,
parse, provenance, persistence, or unexpected-code mismatch. Preserve the
first outcome and do not rerun.

files. The repository, `.env`, RunRecord bodies, Git data, private local paths,

## DRAFT / NOT PUBLISHED — v0.6.0 release notes

### AI Weekly Agent v0.6.0 — Reliable Weekly Runs & History Integrity

This is a local draft. Version 0.6.0 has not been committed, tagged, pushed, or
published.

#### What is included

- Immutable per-attempt raw ResearchRun and Markdown report artifacts.
- An exact-date-range publication manifest written last as publication
  authority, with byte lengths and SHA-256 digests.
- A non-blocking cooperative Linux/WSL `fcntl` lock held from exact-range
  preflight through best-effort attempt telemetry.
- Request-before-work no-overwrite protection in the normal CLI.
- One best-effort `run.json` per attempt, separate from publication authority.
- Manifest-backed and strict legacy mixed-history loading with deterministic
  precedence and authenticated new-format snapshots.

#### Compatibility and usage changes

- New runs use
  `data/raw/<range>/<run_id>.json`,
  `reports/<range>/<run_id>.md`,
  `data/runs/attempts/<range>/<run_id>/run.json`, and
  `data/runs/published/<range>.json`. This is not fully path-compatible with
  tools that assume one ISO-week report or one RunRecord per range.
- Legacy artifacts remain read-only compatible under their existing strict
  canonical-path rules. They are not migrated automatically. The normal data
  root is the current working directory; relative legacy paths retain that
  documented cwd boundary.
- `--overwrite` creates a new immutable attempt and, only after success,
  advances the exact range's manifest. It does not modify old artifacts.
- A present invalid manifest fails closed and does not silently revive
  same-range legacy history. A valid empty publication is authoritative.
- RunRecord remains schema 1 with an optional additive publication summary.
  PublicationManifest has its own schema 1. Compatibility is tested for the
  repository's documented readers, not every unknown external consumer.

#### Validation evidence

- Phase 5 recorded 800 offline tests passing. Phase 6A, after the local version
  update, recorded 175 focused and 800 complete offline tests passing.
- One controlled live candidate run completed with eight logical Responses API
  calls and eight HTTP attempts: six Research, one Curate, and one Report. It
  produced 19 researched candidates, 19 strict Verify acceptances, and 12
  selected stories; manifest publication and later history reconstruction
  succeeded.
- The live candidate still reported application version `0.5.0` at execution
  time. The local `0.6.0` metadata prepared afterward has not been live-tested.
- `OPENAI_MAX_RETRIES=0` was a process-only setting for that controlled
  experiment, not a change to the production default.

#### Known limitations

- Source support and evidence roles are model-reported; they are not
  independent semantic verification of webpage facts.
- Eleven selected stories in the live sample were single-source. Vendor-
  reported benchmark/specification claims and the PrismML/PR Newswire
  `official` classification remain documented content risks.
- Live matched-history classification, `REPEAT` suppression, and selected
  `FOLLOW_UP`/matched-`UNCERTAIN` rendering were not exercised. The earlier
  candidate_005 false-`REPEAT` discrepancy remains unresolved.
- The 27 observed `web_search_call` final-response output items do not prove 27
  completed, unique, billable, or page operations. Per-item status/action and
  exact processing/page/billing counts were not retained.
- The saved wall interval minus summed wrapper call durations is -30.774564
  seconds; the cause is unresolved. Current dollar cost is unknown.
- Locking is cooperative and Linux/WSL-specific. Atomic manifest visibility on
  the tested local filesystem is not a cross-platform transaction or universal
  power-loss guarantee. Hard termination can prevent failure telemetry.
- There is no automatic orphan cleanup, recovery workflow, or legacy migration.

The release does not claim that all facts or history paths are verified, that
performance or cost universally improved, that filesystem transactions are
cross-platform, or that false-`REPEAT` behavior was fixed. Minimal future tool
status telemetry remains an unimplemented idea, not a v0.6.0 feature.
